5. EMAIL APIs
============================================================


------------------------------------------------------------
POST /emails
------------------------------------------------------------

Purpose:

Receives and processes an incoming email.

The email is passed through the Email Agent workflow for
analysis and automated processing.

Method:

POST

Endpoint:

/emails

Request Content-Type:

application/json


Example Request:

{
    "sender": "customer@example.com",
    "subject": "Issue with my order",
    "body": "I received the wrong product."
}


Processing Flow:

Incoming Email
      |
      v
Email API
      |
      v
Email Agent
      |
      v
Intent / Email Analysis
      |
      v
Action Decision
      |
      v
Database / Audit


------------------------------------------------------------
GET /emails
------------------------------------------------------------

Purpose:

Retrieves emails stored in the database.

Method:

GET

Endpoint:

/emails


Example Response:

[
    {
        "id": 1,
        "sender": "customer@example.com",
        "subject": "Issue with my order",
        "body": "I received the wrong product."
    }
]


------------------------------------------------------------
GET /emails/{id}
------------------------------------------------------------

Purpose:

Retrieves a specific email using its ID.

Method:

GET

Endpoint:

/emails/{id}


Example:

GET /emails/1

============================================================
9. API WORKFLOW
============================================================

1. Client sends an email request.

2. Backend receives the request.

3. Email Agent analyzes the email.

4. The system determines the email intent.

5. If required, the system identifies a dispute.

6. Agent decides the appropriate action.

7. Email/dispute information is stored in the database.

8. The performed action is recorded in the audit table.

9. The API returns the result to the client.
